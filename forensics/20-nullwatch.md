# 20-nullwatch

**Category:** Forensics · **Difficulty:** Insane (meta finale)

**Flag:**
```
Null0rigin{the_capture_timestamps_were_stretched}
```

## The meta

This is the finale of the forensics chain, unlocked only after solving all six prior stages: 14-slackwater, 15-handoff, 16-nightshift, 17-greylist, 18-carrier, and 19-revenant.

The final box is sealed by `SHA-256(share_14 || share_15 || ... || share_19)`, where each share is `SHA-256(that stage's flag)[:8]` — the exact convention every stage in the chain used for its own "share for stage 20" value. It is deliberately not built from any mechanical per-stage quantity (a recovered byte offset, an SSRC, a physical address): each of those was excluded from being a share, because a script can obtain them for free without ever doing that stage's actual hard part. A hash of the flag itself can only be produced by whoever already has the flag — so the meta genuinely requires having solved all six stages, not just having poked at their artifacts.

## What ships

`badge-log.txt` states a 200-second window. `capture.pcap` holds 8 packets forming one TCP stream, each carrying a TCP Timestamp option (RFC 7323); the capture's own frame-arrival timestamps span 400 seconds. `case-notes.txt` is a previous analyst's note, left in on purpose: they already tried "the badge log drifted, trust the capture," submitted `Null0rigin{the_badge_reader_drifted}`, and `verify` rejected it. The note contains real information — its reasoning about which timestamp source is easier to forge is correct — sitting right next to a wrong conclusion about which artifact that reasoning actually implicates.

## The mechanism

A capture file's frame-arrival timestamps are libpcap header fields: whatever tool captured or later edited the file wrote them, and nothing about the TCP stream itself depends on them being honest. The TCP Timestamp option is different — it's generated by the sending kernel's own clock and echoed by the receiver, embedded directly in the byte stream. Here it advances at exactly the rate 200 real seconds implies (25s per packet interval, 1000 ms/s), while the pcap's own frame timestamps advance at 400 seconds' worth (50s per interval) — a clean 2x stretch. `badge-log.txt` agrees with the TCP stream's clock, not with the capture's claimed span. The pcap's frame timestamps are the forgery.

## Honesty about scope

The original brief for this stage called for a four-artifact whodunit (disk, memory, pcap, logs) where three of the four artifacts support complete, internally self-consistent, individually-accusable false narratives, and the real tell is a second-order mismatch between the forged pcap's TCP-timestamp slope and a memory image's jiffies-to-uptime ratio implying a different kernel `HZ`. That version couldn't be brought to a standard consistent with the rest of the chain — verified end to end against real bytes, not just asserted in prose — in the time available. Rather than ship a version of that idea that looked elaborate but hadn't actually been checked, this stage keeps the one technique that is real and directly verified against the built artifact (the TSval-vs-frame-timestamp disagreement, confirmed against the actual pcap bytes) and drops the rest. A smaller stage that has been checked beats a bigger one that hasn't.

## The break

1. Parse every TCP segment's Timestamp option; compute the TSval delta across the capture and convert it to seconds.
2. Compare against the pcap's own frame-arrival span — they disagree by 2x.
3. Compare both against `badge-log.txt` — it agrees with TSval, not with the frame span.
4. That identifies the forged artifact; the flag names it.
5. Combine all six shares from stages 14–19 (`SHA-256(flag)[:8]` each, concatenated and hashed) to open `nullwatch.sealed`.

## Solve

`solve/solve.py` performs steps 1–5 mechanically, including actually computing the TSval and frame-timestamp spans from the built pcap (not hardcoding them) and asserting they relate the way the mechanism claims. It uses the six prior stages' actual flags as the input to the final box — consistent with how a player would arrive here, by actually holding all six — and opens the meta box with them.
